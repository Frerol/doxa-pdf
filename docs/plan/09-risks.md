# 09 — Risks

Likelihood (L) and impact (I) use the scale Low/Med/High. Review this register at the end of every milestone.

| ID | Risk | L | I | Mitigation | Owner/When |
|---|---|---|---|---|---|
| R1 | **Ink latency** in Flutter misses the budget on Android (no front-buffer rendering in Flutter) | Low | High | **Retired by Spike B:** 5–7 ms event → raster on the reference device ([ADR-0006](../adr/0006-ink-rendering-in-flutter.md)). Remaining check: camera test before v0.2 | M0 ✓ |
| R2 | **Stylus support gaps on desktop** (affects M5/M6, not the Android MVP): Flutter Windows/Linux embedders may not expose pen pressure/tilt/eraser reliably | High | High | Spike B on real hardware. Fallbacks: contribute upstream fixes, or a small platform plugin that reads Windows Pointer/WM_POINTER and GTK tablet events | M0 |
| R3 | **PDFium crashes** on hostile files take down the whole app (in-process native code) | Med | Med | Fuzzing, timely PDFium updates, journaling so no annotations are lost. Evaluate out-of-process engine (Android service / desktop subprocess) | M0 → M4 |
| R4 | **Annotation interop bugs** (rotation, CropBox, appearance streams) make notes look wrong in other readers | Low | High | Spike C: identical in PDFium, pdf.js, MuPDF, Poppler and a commercial Android reader, incl. rotated/cropped pages. Keep automated cross-renderer tests; Acrobat still to check | M0 ✓, ongoing |
| R5 | **F-Droid** requires building PDFium from source; the build is heavy and fragile | High | Med | Reproducible PDFium build script; ask F-Droid maintainers early; GitHub Releases/Obtainium cover the MVP meanwhile | M5–M7 |
| R6 | **Android storage (SAF)** makes atomic in-place saves hard (content URIs, cloud providers) | Med | High | Spike C: temp → `"wt"` → SHA-256 read-back works on local storage (155 MB in < 1 s). Cloud providers not yet verified; no `FLAG_SUPPORTS_WRITE` → "Save a copy"; journal guarantees recovery | M2 |
| R7 | **Foreign annotation layer** approach (draw own types in Flutter, others in PDFium) proves complex | Low | Med | **Resolved by Spike A:** read-only render instance with Doxa annotations hidden in memory ([ADR-0005](../adr/0005-rendering-pipeline-and-foreign-annotations.md)) | M0 ✓ |
| R8 | **Scope creep** toward a general PDF editor before the study core is excellent | Med | Med | Tier model in Vision §5; every new area needs an ADR; milestone exit criteria | Ongoing |
| R9 | **Bus factor of one** (single maintainer) | High | High | Excellent docs, good-first-issues, CI that enforces quality, clear governance | Ongoing |
| R10 | **Trademark / look-alike concerns** with commercial apps that inspired the feature set | Med | Med | Layout and workflows deliberately follow familiar commercial-reader conventions ([UX §8](05-ux-design.md#8-familiar-layout-and-workflows)), so the visual identity stays original: own name, logo, icons, colours and texts; no copied assets; no other product is named in the repo, store listings or marketing | Ongoing |
| R11 | **Code signing costs** (Windows SmartScreen, Play account fee) | Med | Low | SignPath OSS program; budget for the Play developer fee; MSIX via winget | M6–M7 |
| R15 | **Full saves break digital signatures**, and AP-less markup depends on readers generating appearances (PDF 2.0 requires an AP) | Med | Med | Detect signed PDFs and warn / offer "Save a copy"; own incremental writer with real APs post-MVP ([ADR-0008](../adr/0008-annotation-save-strategy.md)) | M2, post-MVP |
| R12 | Flutter platform breaking changes / pinned version drift | Low | Med | FVM pin, upgrade once per milestone in a dedicated PR | Ongoing |
| R13 | **OCR on-device** is slow or memory-hungry on large scanned books, or its text layer misaligns with the image (bad highlights) | Med | High | Spike D on the reference tablet; `tessdata_fast` models; background per-page queue; word-box alignment tests | M0, M4 |
| R14 | **Large textbooks** (1000+ pages, 100 MB+) exhaust memory or make search/thumbnails slow | Med | High | Spike A: first page ≤ 151 ms, no janky frames on 1000-page and 155 MB files; RSS peaked at 385 MB on the scanned book, so tune budgets and `onTrimMemory`; test a 4 GB device | M0 ✓, M1 |
